      节点说明

      Contract

      正式 spec 里按 ID 定位的规范条目。一个 ID 在所属 spec 内唯一。

      capability:user-auth:session-expiry

      affects 在元数据中声明目标。

      sync 读取 delta 并写入正式规范。

      一个 change 能改哪些地方？

      真实示例 add-passkey-login 的 affects 指向两份 spec。每份 spec 有一份 delta，里面可以声明多条 Contract 操作。

      change · featadd-passkey-login
      • capability:user-auth2 条操作 deltas/capability/user-auth.md
        • MODIFIEDpassword-login
        • ADDEDpasskey-login
      • component:auth-service1 条操作 deltas/component/auth-service.md
        • MODIFIEDcredential-validation
          • 认证服务验证密码或通行密钥凭据，并返回认证结果。
          • 它不负责发送验证码或管理客户端密钥。

      只改 Contract 里的一个 item 呢？

      如果 item 指正文中的一条规则、列表项或场景，它和其他条目都属于同一个 Contract。只改其中一条时，写一段 MODIFIED，带上该 Contract 的完整新正文。图中末端的两句话由同一个 ID 定位。

      如果两条规则各有自己的 Contract ID，就在同一份 delta 中各写一段操作。同步后，历史也按这些 ID 分开保存。

        文件存放在哪里

        目录表达结构与生命周期。每份文件负责不同的信息。

        项目目录

        spec/config.yaml
        声明允许使用的 spec type 和 change kind。
        spec/template/
        specTypes.*.template 指定创建正式 spec 时使用的 Markdown 模板。
        spec/spec-index.md
        CLI 生成的当前规范索引，按 type 列出 spec。
        spec/specs/<type>/<spec-id>/spec.md
        正式规范正文，一份文件可声明多条当前生效的 Contract。
        spec/changes/<status>/<kind>/<change-id>/
        以状态和 kind 组织 change。归档目录名会加日期前缀。
        spec/changes/archived/manifest.json
        记录归档文件的 SHA-256，便于校验封存内容。
        spec/.history/contracts/<type>/<spec-id>/<contract-id>.jsonl
        每条 Contract 的版本。删除后同 ID 再加入，继续沿用原文件和版本号。

        一个 change 的内容

        meta-data.yaml
        id、kind、目标 affects 或 specImpact、正文基线和同步回执。
        change.md
        解释问题和变更目的。
        tasks.md
        记录任务及完成情况。
        deltas/<type>/<spec-id>.md
        有规范影响时，每个目标 spec 对应一份 delta，可以改动其中多条 Contract。

        change 的生命周期

        移动目录会改变 change 的状态。成功 sync 后，change 仍处于 implemented。

        1. proposed起草 change
        2. 校验并完成任务
        3. implemented已完成，可以同步
        4. 检查回执并归档
        5. archived保存材料和校验清单
        proposed → rejected
        保留未采纳的理由，结束同步和归档流程。
        specImpact.kind: none
        适用于没有正式规范影响的 change。完成后可直接归档。
        proposed
        显示恢复申请处理进度
        implemented
        恢复统一的验证次数规则
        rejected
        直接显示恢复方式是否已绑定
        archived
        统一账号恢复校验与通知

        页面使用仓库示例快照，更新仓库后需重新导出页面数据。
