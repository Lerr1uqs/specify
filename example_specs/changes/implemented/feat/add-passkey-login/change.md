# 背景

当前认证服务只支持密码登录。部分用户希望使用设备内置的通行密钥完成登录。

# 目标和范围

通行密钥可以减少密码输入，并让认证服务统一处理不同类型的凭据。本次支持使用已注册的通行密钥登录，并在服务端验证凭据。

通行密钥注册界面、跨设备同步和账户恢复流程不在本次范围内。

# 设计

复用现有会话签发流程，在凭据验证层增加通行密钥验证分支。认证结果和会话签发由同一服务负责，避免客户端自行决定认证成功。

不采用由网关验证后转发用户身份的方案，因为网关不应承担凭据验证和会话授权职责。

# 风险与迁移

通行密钥验证库升级可能改变断言格式；在认证服务边界统一解析，并为格式升级增加兼容验证。旧密码登录接口保持兼容，客户端可逐步启用通行密钥。
